# Simple v1 local implementation review

Date: October 20, 2026. Branch: `site/simple-v1`. This is a local implementation record, not a release approval.

## Built

The existing animated wave, grayscale client-logo reveal and HVA identity remain.

The Case Studies index and the three named client details use approved records, full challenge/delivery fields, actual screenshots and available published evidence. About uses real founder profiles. Contact presents the existing form, contact facts and next steps.
- The Insights hub, blog, news, perspectives and research indexes and detail routes retain their Sanity content, URLs and available translations in the simpler shared shell. Article headlines now use the approved Manrope role; section headings use Newsreader. The policy pages preserve their reviewed text in a readable layout.
- Structured data and metadata cover the core destinations and editorial families. Index ItemLists use their actual linked records; article types and authors follow the source content. Publication dates are retained, and unsupported modification dates were removed. No review ratings, fictitious metrics or calendar availability were added.

## Remaining dependencies and inherited findings

- The Spanish and Arabic service/founder records have localized `visibility` and `profileType` values in Sanity. The public site now recognizes the observed approved values, but the CMS fields should eventually use language-independent stored keys so future translations cannot silently hide published pages. No CMS records were changed during this implementation.
- The owner's calendar tool has no integration URL or contract yet. Current calls lead to an honest enquiry; without a contact API the form opens a prepared email draft that the visitor must send.
- The 12 currently published research-report translations (three reports in four languages) contain one short section each, 11–26 words of report body, and no source list in Sanity. Their current pages correctly render that supplied content, but a substantive report-reading experience needs approved research copy and sources added to the CMS. This follows the owner's direction to reuse existing CMS content for now.
- The report-mode brand audit still reports **448 inherited blocking occurrences** in older site files. The responsive audit passes. `audit:seo-artifacts` reports **214 overdue claim reviews** from the existing claim registry. These are tracked separately from the new page build; the older retained URLs are not silently redirected or removed.
- A local site cannot be fetched by Google's URL-based Rich Results Test. Search Console review, production Core Web Vitals and the logo's commercial license review belong to release preparation. Local schema parsing and source checks do not imply eligibility for a rich result.
- The validator's code-snippet mode did accept four local JSON-LD samples. Its follow-up warning review is still pending after rate limiting; zero syntax errors in the initial samples does not mean the remaining warnings are resolved. Google's URL-based Rich Results Test and production Search Console checks still require a public release.
- Industry, location and other retained destinations keep their inherited layouts pending the route-by-route migration review specified in the [site plan](simple-v1-site-plan.md). The service-detail family now uses the Simple v1 layout. All current sitemap destinations remain reachable.

No push, merge, CMS publication or deployment was made. The full site remains on `main`, with `site/enterprise-maintained` preserved for its continued maintenance.
